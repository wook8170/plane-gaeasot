# 공용 패키지 및 라이브러리 분석 (Shared Packages)

이 문서는 `packages/` 폴더 내에 위치하여 여러 서비스(Web, Admin, Space 등)에서 공통으로 가져다 쓰는 핵심 코드 조각들을 분석한 내용입니다.

## 1. 핵심 패키지 구성 및 역할

| 패키지명      | 주요 역할        | 상세 설명                                                                              |
| :------------ | :--------------- | :------------------------------------------------------------------------------------- |
| **propel**    | 디자인 시스템    | 버튼, 입력창, 모달 등 일관된 UI를 유지하기 위한 컴포넌트 라이브러리입니다.             |
| **editor**    | 에디터 엔진      | 문서 및 이슈 설명 작성을 위한 블록형 리치 텍스트 에디터의 핵심 로직입니다.             |
| **types**     | 데이터 타입 정의 | 이슈, 사용자 등 시스템 전반에서 쓰이는 공통 데이터 모델의 TypeScript 인터페이스입니다. |
| **ui**        | 부가 UI 요소     | `propel` 보다는 좀 더 복합적인 화면 요소(복잡한 필터링 레이아웃 등)가 담겨 있습니다.   |
| **constants** | 전역 상수        | 서버 주소, 기본 설정값, 고정된 메시지 문구 등을 관리합니다.                            |
| **utils**     | 공통 유틸리티    | 시간 계산, 텍스트 변환, 색상 처리 등 단순하고 반복되는 기능을 담은 함수들입니다.       |

---

## 2. 디자인 시스템 활용 가이드 (Propel)

Plane.so는 자체 제작한 디자인 시스템인 **Propel**을 통해 세련되고 일관된 사용자 경험을 제공합니다.

- **기술 기반**: Tailwind CSS와 Radix UI를 기반으로 구축되었습니다.
- **파일 위치**: `packages/propel/src` 내에 각 컴포넌트별 소스 코드가 위치합니다.
- **활용법**: 프론트엔드 앱인 `apps/web` 등에서 `@plane/propel` 패키지를 통해 손쉽게 가져다 씁니다. (예: `import { Button } from "@plane/propel";`)

---

## 3. 문서 편집 엔진 (Editor)

이 프로젝트의 강점인 협업 에디터는 별도의 패키지로 분리되어 관리됩니다.

- **구조 특징**: 한 줄 한 줄이 객체로 관리되는 블록 기반 구조로, 확장이 매우 자유롭습니다.
- **실시간 연동**: `packages/editor` 패키지 내부에 실시간 통신을 위한 로직이 내장되어 있어, 어떤 화면에서도 에디터를 불러오면 즉시 실시간 협업이 가능해집니다.

---

## 4. 모노레포 관리 및 의존성 (Turbo/PNPM)

여러 패키지를 하나의 저장소에서 관리하기 위해 모노레포(Monorepo) 기법을 사용합니다.

- **PNPM 워크스페이스**: 패키지 간의 복잡한 연결 관계를 효율적으로 처리하며 디스크 용량을 절약합니다.
- **터보레포 (Turborepo)**: 변경된 부분만 골라서 빌드하거나 테스트하여 개발 속도를 획기적으로 높여줍니다.
- **공유 설정**: ESLint(코드 스타일 체크), Prettier(자동 정렬) 등의 개발 도구 설정도 패키지 형태로 공유하여 팀원 모두가 동일한 코드 품질을 유지하도록 돕습니다.

---

## 5. 수정 시 주의사항

1.  **전역 영향도 체크**: `packages/` 내의 코드를 수정하면 이를 참조하는 모든 앱(Web, Admin, Space 등)에 동시에 반영되므로, 수정 전 영향 범위를 반드시 파악해야 합니다.
2.  **타입 일치**: 백엔드에서 데이터 구조를 변경했다면, 반드시 `packages/types`의 인터페이스도 함께 업데이트하여 프론트엔드에서 오류가 발생하지 않도록 해야 합니다.
3.  **순환 참조 주의**: 패키지 A가 B를 참조하고, B가 다시 A를 참조하는 순환 참조 구조가 생기지 않도록 설계 단계에서 주의가 필요합니다.
