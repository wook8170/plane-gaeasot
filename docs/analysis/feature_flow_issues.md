# 주요 기능 연쇄 동작 분석 (이슈 관리 로직)

이 문서는 Plane.so의 가장 핵심 기능인 '이슈(Issue)'가 사용자의 동작부터 실제 데이터베이스 저장까지 어떻게 단계별(Cascading)로 이어지는지 분석한 문서입니다.

## 1. 이슈 생성 과정 (Issue Creation Lifecycle)

사용자가 새로운 작업을 등록할 때 발생하는 내부 동작 순서입니다.

| 단계             | 수행 위치 (소스 코드 경로)                   | 상세 동작 설명                                                                              |
| :--------------- | :------------------------------------------- | :------------------------------------------------------------------------------------------ |
| **1. UI 입력**   | `web/core/components/issues/issue-modal.tsx` | 사용자가 제목, 설명, 담당자 등을 입력하고 저장 버튼을 클릭합니다.                           |
| **2. 상태 관리** | `web/core/store/issue/issue.store.ts`        | MobX 스토어에서 데이터를 정리하고 API 서비스를 호출합니다.                                  |
| **3. API 통신**  | `web/core/services/issue/issue.service.ts`   | 브라우저에서 백엔드 서버의 `/api/.../issues/` 주소로 데이터를 전송합니다.                   |
| **4. 서버 수신** | `api/plane/app/views/issue/base.py`          | 백엔드 서버의 `IssueViewSet`이 요청을 효율적으로 수신합니다.                                |
| **5. 검증/정제** | `api/plane/app/serializers/issue.py`         | 입력된 제목의 길이를 체크하고, 설명(HTML) 내의 위험한 코드를 제거(Sanitizing)합니다.        |
| **6. DB 저장**   | `api/plane/db/models/issue.py`               | 최종적으로 DB 테이블에 값을 기록합니다. 이때 담당자, 라벨 등 연결 데이터도 함께 저장됩니다. |
| **7. 후속 작업** | `api/plane/bgtasks/issue_activities_task.py` | "누가 이슈를 생성했다"는 활동 이력(Activity)을 남기기 위한 비동기 작업이 실행됩니다.        |

---

## 2. 프로젝트 및 권한 구조 (Cascading Permissions)

이슈는 프로젝트에 소속되며, 설정 정보는 상위에서 하위로 상속(Cascading)됩니다.

- **워크스페이스(Workspace)**: 가장 최상위 단위로, 전체 프로젝트의 요금제나 기본 설정을 관리합니다.
- **프로젝트(Project)**: 이슈들의 컨테이너입니다. 여기에서 정의된 '상태(State)', '라벨(Label)', '우선순위 종류' 등이 하위 이슈들에게 적용됩니다.
- **멤버 권한**: 프로젝트별로 소유자(Owner), 관리자(Admin), 멤버, 게스트 권한이 있으며, 백엔드의 시리얼라이저(`Serializer`) 단계에서 이 권한을 꼼꼼하게 체크합니다.

---

## 3. 실시간 협업 에디터 연동

이슈 설명(Description)이나 문서(Pages) 수정 시 실시간으로 동기화되는 방식입니다.

1.  **에디터 인터페이스**: `packages/editor` 패키지에 정의된 블록 단위 에디터를 사용하여 복잡한 문서 구조를 관리합니다.
2.  **연결 방식**: 사용자가 글을 쓰는 즉시 `apps/live` 서버로 변경 데이터 조각이 날아갑니다.
3.  **병합 처리**: 여러 사용자가 동시에 같은 부분을 수정할 경우, Yjs 라이브러리의 병합 알고리즘이 서버측에서 충돌 없이 합쳐줍니다.
4.  **최종 기록**: 합쳐진 최종 문서 데이터는 백엔드 API를 통해 PostgreSQL의 `Page` 관련 테이블에 최종 저장됩니다.

---

## 4. 개발 시 주의사항

- **API 버전 확인**: 최신 기능은 주로 `v2` 경로의 API를 사용하므로 서비스 연동 시 끝점(Endpoint) 주소를 확인해야 합니다.
- **파일 첨부**: 이슈에 파일을 첨부할 때는 MinIO 저장소를 직접 거치지 않고 직접 업로드하거나 pre-signed URL을 받아 처리하는 로직을 따릅니다.
- **성능 최적화**: 이슈가 많아질 경우 화면 속도가 느려질 수 있으므로, 프론트엔드에서는 가상 리스트(Virtual List)나 지연 로딩(Lazy Loading) 기법이 적용되어 있습니다.
