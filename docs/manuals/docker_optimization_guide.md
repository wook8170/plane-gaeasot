# 도커 설정 최적화 가이드 (Docker Optimization Guide)

이 문서는 Plane.so 개발 환경을 위해 최적화된 도커(Docker) 설정의 주요 변경 사항과 사용 방법을 설명합니다.

## 1. 주요 최적화 사항

### 1.1 데이터 지속성 및 접근성 개선 (바인드 마운트)

기존의 이름 있는 볼륨(Named Volume) 대신 로컬 디렉토리를 직접 연결하는 **바인드 마운트(Bind Mount)** 방식을 채택했습니다. 모든 데이터는 프로젝트 루트의 `docker_data` 폴더에 물리적으로 저장됩니다.

- **데이터베이스(DB) 데이터**: `./docker_data/db` -> PostgreSQL 데이터 저장
- **레디스(Redis) 데이터**: `./docker_data/redis` -> Valkey(Redis) 데이터 저장
- **메시지 큐(RabbitMQ)**: `./docker_data/rabbitmq` -> RabbitMQ 데이터 저장
- **파일 업로드**: `./docker_data/uploads` -> MinIO(S3 호환 저장소) 데이터

**장점**: 컨테이너를 삭제하거나 초기화해도 데이터가 유지되며, 로컬에서 직접 파일을 확인하거나 백업하기가 매우 쉽습니다.

### 1.2 실시간 코드 반영 (핫 리로드, Hot-Reload)

개발 효율을 높이기 위해 로컬 소스 코드를 컨테이너와 실시간으로 동기화합니다.

- **프론트엔드 (web, admin, space)**: 로컬 소스가 컨테이너의 `/app` 경로에 연결되어 `pnpm run dev` 실행 시 코드 변경 사항이 즉시 화면에 반영됩니다.
- **백엔드 (api)**: Django의 `runserver` 기능을 사용하여 Python 코드 수정 시 서버가 자동으로 재시작됩니다.
- **백그라운드 워커 (worker)**: `watchfiles` 패키지를 추가하여 워커 로직 수정 시에도 컨테이너 재시작 없이 자동으로 반영되도록 설정했습니다.

### 1.3 의존성 관리 및 빌드 최적화

- **설정 서비스 (setup)**: 의존성 설치(pnpm install) 과정을 별도의 서비스로 분리하여, 프론트엔드 서비스들이 시작되기 전 최신 상태를 보장받도록 했습니다.
- **Valkey 채택**: Redis의 오픈 소스 대안인 Valkey를 사용하여 가볍고 안정적인 서비즈 구조를 유지합니다.

## 2. 주요 서비스 및 접속 정보

| 서비스명        | 역할 설명                     | 외부 포트 | 내부 포트 |
| :-------------- | :---------------------------- | :-------- | :-------- |
| **proxy**       | 전체 시스템 관문 (Caddy)      | **9000**  | 80        |

| **web**         | 메인 사용자 화면 (Next.js)    | -         | 3000      |

| **plane-db**    | 데이터베이스 (PostgreSQL)     | **9010**  | 5432      |
| **plane-minio** | 파일 저장소 관리 화면         | **9006**  | 9090      |

## 3. 관리 명령어 안내

### 서비스 시작 (백그라운드)

```bash
docker compose up -d
```

### 특정 서비스 로그 확인

```bash
docker compose logs -f [서비스명]
```

### 서비스 중지

```bash
docker compose down
```

---

## 4. 주의 사항

1.  **파일 권한**: `docker_data` 폴더 내의 파일 권한 문제로 컨테이너 실행이 안 될 경우, 로컬에서 `sudo chown -R $USER:$USER docker_data` 명령으로 권한을 조정해 주세요.
2.  **환경 설정**: 모든 포트와 계정 정보는 `.env` 파일에서 관리됩니다. 정보를 수정한 후에는 반드시 컨테이너를 재시작해야 적용됩니다.
